# 10. Narrative Operators

## 1. 职责

把叙事结构做成**离散的、可调度的算子**：确定性系统决定用哪个算子，LLM 只在算子给定的槽位里填内容。

解决的问题是自由生成的内容"局部合理、整体无形状"——每句都通顺，但没有铺垫和回收，没有逐步逼近核心的推进感。

## 2. 三类算子

### 2.1 状态算子（确定性）

改变世界，不生成文本。一个算子 = **一组 Action Proposal**，因此走既有的 Validator，无需新权限机制。

| 算子 | 作用 | 本场景中的形态 | 是否实现 |
|---|---|---|---|
| `foreshadow` | 埋下未来会回收的伏笔 | 写入 hidden fact + 登记进伏笔账本 | 是 |
| `reveal` | 让已可解锁的信息进入玩家视野 | 玛尔塔说出线索 | 是 |
| `escalate` | 提升某条线的紧迫度 | 洛伦察觉玩家在调查 | 是 |
| `reverse` | 不给新信息，改变已知信息的含义 | 见 §5 | 是 |
| `relieve` | 降张力，给玩家喘息 | 本轮不触发任何算子（隐式） | 隐式 |
| `complicate` | 让已解决的事重新出问题 | — | 否，单线场景无必要 |
| `converge` | 接上两条独立线索 | — | 否，只有一条主线 |

### 2.2 选择算子（确定性）

即 Experience Controller，两段式，见 §3。

### 2.3 生成算子（LLM）

在算子给定的槽位里填内容。算子提供的输入包括戏剧功能、参与者、以及**显式的禁止项**（如"不能揭露洛伦的身份"）。

## 3. 选择：张力准入 + 偏好排序

偏好和张力是两个正交维度，**分两段处理，不相乘**：

| 维度 | 含义 | 变化频率 | 用法 |
|---|---|---|---|
| 张力 | 现在该多紧 | 每个 beat 都在变 | 硬过滤（准入） |
| 偏好 | 玩家口味（探索/社交/阴谋） | 会话内基本不变 | 软打分（排序） |

相乘会导致"对味但不是时候"的候选仍然得高分——玩家偏好阴谋，刚连着三次揭露，第四个阴谋 beat 依然不该出。

代码见 [05_Narrative_Engine.md](./05_Narrative_Engine.md#22-experience-controller候选事件准入-排序确定性)。

### 3.1 节奏规则（张力准入的全部内容）

本场景只实现节奏约束，不做张力曲线拟合（一局 15-30 轮，曲线拟合无意义）：

- 不能连续两轮 `reveal`
- 不能连续 N 轮没有任何算子触发
- `escalate` 之后至少隔一轮才能再 `escalate`

判断依据是 `story_beats.recent_operators`。

### 3.2 张力的来源

本场景无战斗无数值，张力由三项构成：

| 来源 | 字段 |
|---|---|
| 逼近答案的程度 | `quests.investigation.stage` |
| 威胁 | `npc_a_threatened`（"说出去你儿子会是下一个"） |
| 不确定性 | 处于 `partial` 状态的 fact 数量 |

一个未实现的低成本杠杆：`npc_b_aware_of_investigation`（洛伦是否知道玩家在调查）。一个布尔值即可把"走访证人"变成"被盯上了"。

## 4. 伏笔账本

`foreshadow` / `payoff` 必须成对。账本存在 `story_beats.open_foreshadowings`：

```
foreshadow → 写入 hidden Fact + 登记账本条目
                        ↓ (每个决策点检查)
     未回收的有哪些？到回收时机了吗？超期了吗？
                        ↓
payoff → 回收，从账本移除
```

每条账本条目记录：

| 字段 | 说明 |
|---|---|
| `fact_id` | 对应的 hidden fact |
| `planted_at_turn` | 埋下的轮次 |
| `payoff_condition` | 结构化条件（`{path, op, value}`），可被求值器判定 |
| `overdue_after_turns` | 超期阈值 |

`payoff_condition` 必须是结构化条件而非自由文本，否则账本无法自动判断"到时机了吗"。

可视化见 [07_Observability.md](./07_Observability.md#23-narrative-state-panel叙事状态面板)，指标见 [08_Evaluation.md](./08_Evaluation.md#21-叙事结构指标)。

## 5. 结构质量优先级

按坏掉之后的伤害排序。这个顺序决定实现和排查问题的先后。

| 优先级 | 项目 | 状态 | 说明 |
|---|---|---|---|
| 1 | 不自相矛盾 | 大部分由架构保证 | 事实源唯一 + NPC 只能说可见集合内的内容。度量见 [08 §2.1](./08_Evaluation.md#21-叙事结构指标) |
| 2 | 反转 | 触发条件已在剧本中 | `npc_a_threatened` 解锁后，玛尔塔此前的回避从"包庇"重读为"护子"。复用已有信息，不增加认知负担 |
| 3 | 伏笔回收 | 见 §4 | |
| 4 | 收束 | 待实现 | 3 个结局：查明真相 / 被洛伦先动手 / 玛尔塔彻底闭口（fear 过高） |
| 5 | 戏剧性反讽 | 不在本场景 | 需要 `visibility` 从"每 fact 一态"改为"每观察者一态" |

## 6. 与现有模块的对应

引入算子不新增模块：

| 模块 | 角色 |
|---|---|
| `check_triggers()` | 产出候选算子（带 `operator` 字段） |
| Experience Controller | 张力准入 + 偏好排序 |
| `generate_content()` | 在算子槽位里填内容 |
| Action Proposal / Validator | 算子效果的落地路径，不变 |
| `Fact` + `reveal_condition` | 伏笔账本的存储基础 |

## 7. 实现约定

- 实现 4 个算子（§2.1 表格），`relieve` 用"本轮不触发"隐式表达。
- 张力只做 §3.1 的节奏规则。
- 伏笔账本先做记录 + 超期告警 + 可视化；自动选择回收时机留作后续。
- `StoryBeats` schema 见 [04 §4.1](./04_World_State_Manager.md#41-storybeats切片-3-引入当前未实现)，切片 3 引入。
- 生成算子的 prompt 经 [11_Prompt_Lab.md](./11_Prompt_Lab.md) 选定。
