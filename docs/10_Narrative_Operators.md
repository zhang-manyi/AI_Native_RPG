# 10. Narrative Operators

## 1. 问题

把 world state 和 persona 交给 LLM 自由生成剧情，产出的内容会是**局部合理、整体无形状**的：每一句都通顺、都符合人设，但没有铺垫和回收，没有逐步逼近核心的感觉。

这不是文笔问题。LLM 优化的是下一个 token 的合理性，而叙事吸引力来自**跨越很长跨度的结构关系**——第 12 轮的爆发之所以有力，是因为第 2 轮埋了那个东西。这个跨度远超模型在无约束生成时会自发维持的范围。

解法：**把结构做成离散的、可调度的算子，由确定性系统决定用哪个，LLM 只在算子给定的槽位里填内容。** 这是 [01_System_Architecture.md](./01_System_Architecture.md) "按是否需要 LLM 分层"在叙事维度上的重演。

概念来源：Propp 的故事功能分析（算子集合可枚举）、Facade 的 beat 概念（叙事单元 = 前置条件 + 功能 + 效果）、RimWorld / Left 4 Dead 的 AI Director（按张力曲线调度）。第二条与本架构同构——Narrative Engine 已经是一个规则触发的 drama manager，`EventCandidate` 就是候选 beat。

## 2. 三类算子

### 2.1 状态算子（确定性）

改变世界，不生成文本。一个算子 = **一组 Action Proposal**，因此天然走 Validator，不需要新的权限机制。

| 算子 | 作用 | 本场景中的形态 |
|---|---|---|
| `foreshadow` | 埋下未来会回收的伏笔 | 写入一条 hidden fact，登记进伏笔账本 |
| `reveal` | 让已可解锁的信息进入玩家视野 | 玛尔塔说出线索 |
| `escalate` | 提升某条线的紧迫度 | 洛伦察觉玩家在调查 |
| `reverse` | 不给新信息，改变已知信息的含义 | 见 §4.2 |
| `relieve` | 降张力，给玩家喘息 | 本轮不触发任何算子（隐式） |
| `complicate` / `converge` | 让已解决的事重新出问题 / 接上两条线索 | 不做：单线场景无必要 |

### 2.2 选择算子（确定性）

即 Experience Controller，**张力准入 + 偏好排序**两段，见 §3。

### 2.3 生成算子（LLM）

在算子给定的槽位里填内容。算子已规定这一场的戏剧功能和约束（如"foreshadow，涉及玛尔塔，不能揭露洛伦身份"），LLM 只负责写成台词。约束越具体，输出越不容易跑偏——算子的作用是把"写得有吸引力"这个无法下达的要求，翻译成模型能执行的局部指令。

## 3. 偏好与张力是两个正交维度

| 维度 | 是什么 | 变化频率 |
|---|---|---|
| **偏好** | 口味轴（探索 / 社交 / 阴谋） | 一个会话内基本不变 |
| **张力** | 时间轴（现在该多紧） | 每个 beat 都在变 |

**不能相乘**：乘式无法表达"对味但不是时候"——玩家偏好阴谋，但刚连着三次揭露，第四次阴谋 beat 依然是错的，而乘法里偏好那一项还在加分。

正确结构是两段：**张力准入（硬过滤）→ 偏好排序（软打分）**，代码见 [05_Narrative_Engine.md](./05_Narrative_Engine.md#22-experience-controller候选事件准入--排序确定性)。

### 3.1 本场景的张力从哪来

没有战斗和数值，但张力的货币不一样。侦探故事的张力由三样构成：

- **逼近答案的程度**：`quests.investigation.stage`
- **威胁**：`npc_a_threatened`（"说出去你儿子会是下一个"）是零战斗的张力源
- **不确定性**：多少 fact 处于 `partial`（知道有事但不知道是什么）

一个尚未实现、成本极低的杠杆：**洛伦是否知道玩家在调查**。这一个 bit 就把"走访证人"变成"被盯上了"。

### 3.2 只做节奏约束，不做张力曲线

一局 15-30 轮，画完整起承转合曲线是过度设计。只取最有用的部分：

- 不能连续两轮 `reveal`（信息倾泻）
- 不能连续 N 轮什么都没发生（停滞）
- `escalate` 之后至少隔一轮才能再 `escalate`

纯规则、可单测，且已经能挡住 LLM 自由生成最常见的两种失败：一次说太多，和什么都没推进。

## 4. 结构质量的优先级

按"坏掉之后玩家感受到的伤害"排序。

### 4.1 不自相矛盾（最高）

NPC 第 3 轮说的和第 20 轮说的不能冲突。**缺伏笔是平淡，矛盾是崩坏。** 本架构已免费拿到大半：事实源唯一，NPC 说的话只能来自其可见集合，就没有编造空间。度量见 [08_Evaluation.md](./08_Evaluation.md#21-叙事结构指标)。

### 4.2 反转（本场景性价比最高）

不揭露新信息，而让**已知信息改变含义**。本场景已埋好触发条件：`npc_a_threatened` 一旦解锁（`all[trust>=70, fear<=20]`——要先让玛尔塔不怕才肯说），她此前所有回避都从"包庇凶手"重读成"保护儿子"。玩家手上信息一条没变，意义全变了。

复用已有信息、不增加认知负担，而"重新理解一遍"的体验强度远高于"又拿到一条线索"。

### 4.3 伏笔回收

`foreshadow` / `payoff` 是唯一必须成对的算子，也是 LLM 最做不到的事（埋下时不记得回收）。但埋伏笔本身就是一次世界状态写入，所以可以用确定性代码解决：

```
foreshadow → 写入 hidden Fact + 登记进 story_beats.open_foreshadowings
                            ↓ (每个决策点检查)
        有哪些未回收？到回收时机了吗？超期了吗？
                            ↓
payoff → 回收，从账本移除
```

账本每条记：埋下轮次、`payoff_condition`（结构化条件，可被求值器判定）、超期阈值。可视化见 [07_Observability.md](./07_Observability.md#23-narrative-state-panel叙事状态面板)，指标见 [08_Evaluation.md](./08_Evaluation.md#21-叙事结构指标)。

### 4.4 收束

至少 3 个结局，否则是技术演示而不是故事：查明真相 / 被洛伦先动手 / 玛尔塔彻底闭口（fear 过高）。成本很低，但没有它整个体验没有形状。

### 4.5 戏剧性反讽（扩展点，不在本场景）

玩家知道 NPC 不知道的事，或反过来。需要 `visibility` 从"每 fact 一态"改成"每观察者一态"。记下口子在哪，本场景不做。

## 5. 与现有模块的关系

引入算子**不新增模块**，只是把已有模块的职责说得更具体：

| 已有模块 | 引入算子后的角色 |
|---|---|
| `check_triggers()` | 产出候选**算子**（带 `operator` 字段），而非笼统的"事件" |
| Experience Controller | 张力准入 + 偏好排序两段 |
| `generate_content()` | 在算子给定的槽位里填内容 |
| Action Proposal / Validator | 算子的效果落地路径，不变 |
| `Fact` + `reveal_condition` | 伏笔账本的存储基础 |

## 6. 实现约定

- 只实现 `foreshadow` / `reveal` / `escalate` / `reverse` 四个，`relieve` 用"本轮不触发"隐式表达。
- 张力只做 §3.2 的节奏约束，不做曲线拟合。
- 伏笔账本先做记录 + 超期告警 + 可视化，自动选择回收时机留作后续。
- `StoryBeats` schema 先定全（见 [04_World_State_Manager.md](./04_World_State_Manager.md#41-storybeats)），调度逻辑后续填。
