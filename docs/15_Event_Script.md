# 15. Event Script：事件编排

机制在 [13_Narrative_Events.md](./13_Narrative_Events.md)，内容与结局在 [14_Case_Design.md](./14_Case_Design.md)。本文档是**编排**：每个事件的完整定义、判定规则、依赖图、以及时段预算的验算。

写这一篇的目的之一是**在写代码前发现 schema 缺口**（[14 §8](./14_Case_Design.md#8-内容设计的检查项) 检查项第 4 条）。缺口汇总在 §7。

## 1. 玩家侧的三种形态

不是每句话都要选。理由不只是体验：**如果每句都是带标签的选项，标签就通货膨胀了**——玩家点第二十个 [示好] 时它已经没有分量，而且每句都像检定就成了对话树。反过来，大部分推进自然发生时，**选择出现的那一刻本身就是信号：这里重要**。

| 形态 | 用在哪 | 作用 |
|---|---|---|
| **剧本台词**（玩家自发说出） | 开场、过渡、没有分歧处 | 推进节奏，不消耗决策力 |
| **带标签的选项** | 关键处：结果集真的分叉 | 决策点，标签让玩家知道自己在赌什么 |
| **自由输入** | 始终可用 | Agent 能力的展示位（[03 §5](./03_Player_Model.md#5-当前实现范围)） |

**判据**：一个位置的所有选项若导致同样的结果集，它就不该是选项。这条可执行——事件定义里结果集只有一个的地方，自动用剧本台词。

剧本台词这一档顺带修掉一个别扭之处：实测那局玩家打了"我想打听一下"、"好的"、"嗯嗯好"——这些不是决策，是为了让对话继续下去的填充。变成剧本台词后玩家输入次数下降，每次输入的含金量上升。

### 1.1 自由输入等同于选项

玩家自由输入的内容若等同于某个选项，**就按那个选项判定**（复用 NPC 那次调用顺带分类，[03 §5](./03_Player_Model.md#5-当前实现范围) 的 `player_intent_tag` 手法）。

否则玩家会发现打字比点按钮吃亏（选项有明确判定，打字没有），于是所有人只点按钮，自由输入这条路就死了。

反过来说，这让**选项成为词汇表而不是菜单**：它告诉玩家"这里可以示好、可以试探"，而玩家可以用自己的话做同一件事，甚至做一件选项没列的事。这既保住了可控与省 token，也保住了 [03 §5](./03_Player_Model.md#5-当前实现范围) 那条"不能降级成状态机查表"。

## 2. 四个标签

标签命名的是**这句话对她做了什么**，不是玩家的技能。没有技能系统，决定成败的是她对你的 `trust` 和她的 traits——标签名若承诺一套不存在的系统（"我的共感有多高？"），那是设计债。

| 标签 | 动的是 | `PreferenceTag` | 要判定吗 |
|---|---|---|---|
| **[示好]** | trust + | `social` | 否，只有幅度差异 |
| **[追问]** | fear +，trust 可能 - | `intrigue` | 是，但判的是"值不值"而非"能不能" |
| **[试探]** | 成 trust +，败 trust - / fear + | `intrigue` | 是，随机带最宽 |
| **[观察]** | 不动关系值 | `exploration` | 否 |
| （无标签） | — | — | 否 |

**不对称是有意的**。全都判定的话 [示好] 会变成一个莫名会失败的动作，既挫败也违反直觉。玩家会学到"有些选项稳、有些险"，这正是可学习的东西。

[观察] 单独存在有两个理由：探索型玩家在玛尔塔家除说话外无事可做，`exploration` 收不到信号；而它是**唯一不动关系值的选项**，因此是"不想冒险但想推进"的出口——fear 很高时玩家会需要它。

**不给标签配数字**（不写 `[示好 65%]`）。那会暴露 §3 的判定位置，而整个设计是"玩家看不到自己在哪一段"。要提示就用定性的状态描述（"她还很警惕"），那是反应型旁白的正当内容（[13 §5](./13_Narrative_Events.md#5-声音层次)）。

## 3. 判定：三段式 + 信息不对称

目标是"有控制感但无法完全控制"。达成手段**不是骰子**：

| 差距（当前值 vs 门槛） | 结果 |
|---|---|
| 低于门槛 8 以上 | 必败 |
| 门槛 ±8 以内 | 随机 |
| 高于门槛 8 以上 | 必成 |

**关键在于玩家看不到自己在哪一段。** 他知道她"还很警惕"（定性），不知道 trust 是 33 还是 41（定量）。所以判定确定而体验不确定——**不确定性来自认知不完整，而非系统掷骰**。

比纯随机好在三处：

- **可复现**。[07](./07_Observability.md) 的立场是 trace 可复现、面板能解释为什么失败；纯随机让面板只能显示"运气不好"。
- **可学习**。玩家从失败里学到"她还不够信我"，而不是"我运气差"。控制感的真正来源。
- **可测**。确定性部分严格先写测试（[09 §5](./09_Reference_Scenario.md#5-测试策略)），随机判定只能测分布。

**随机带宽度按标签而异，这本身是设计语言**：

| 标签 | 带宽 | 理由 |
|---|---|---|
| [试探] | ±12 | 本质是赌，宽带表达这件事 |
| [追问] | ±8 | 标准 |
| [示好] / [观察] | 0（不判定） | 只有幅度差异 |

### 3.1 数值变化受 `MAX_RELATIONSHIP_STEP` 约束

`MAX_RELATIONSHIP_STEP = 15`，Validator 强制。所以**单个结果的关系值变化不得超过 ±15**，本文档所有数值都在此范围内。

这不是限制而是保障：它意味着 trust 从 10 走到 85（`loren_that_night` 门槛）**至少需要 5 个事件**，没有任何单一动作能跳过整条社交线。[04](./04_World_State_Manager.md) 设这个上限正是为此。

### 3.2 幅度随当前状态浮动

[示好] 的效果取决于她当前的警惕程度：

| 当前 trust | [示好] 效果 | 读起来是 |
|---|---|---|
| < 25 | +8 | 她还警惕，但听进去了 |
| 25–55 | +12 | 有效果 |
| > 55 | +15（`MAX_RELATIONSHIP_STEP` 上限） | 她愿意听你说话了 |

这条曲线是**递增**的，因为信任的建立本身是加速的。它也顺带解决"进展慢"：早期慢是对的（她怕你），中期该快起来。

这组数字是 §6.1 验算的结果，不是拍的。第一版取 `+3 / +8 / +12`，验算发现 12 个时段走不到 M3 的 trust 40 门槛——**"进展慢"的定量重现**，同一个原因：单步增量相对门槛太小。低档从 +3 抬到 +8 是那次验算的修正。

### 3.3 失败后果：可重来为主，两个关键事件永久关闭

| 后果 | 代价 | 用在哪 |
|---|---|---|
| 落默认结果 | 一个时段 | 大部分事件 |
| 永久关闭 | 这条信息只能从别处拿 | 只有 M3、M5 |

全都可重来会让时段成本失去意义；全都永久关闭会让玩家不敢碰任何有风险的选项，最后只点 [示好]——那反而减少了选择。

永久关闭的两个事件都**有替代通道**（M3 可由酒馆 + 物证绕过，M5 可由 M4 的时间线绕过），所以关闭是代价而非死局。这是 [14 §4.3](./14_Case_Design.md#43-被洛伦先动手-玛尔塔彻底闭口) 对"闭口"的同一种处理：代价，不是墓碑。

## 4. 事件定义

命名：`M` 主线（`reveal` 为主），`F` 铺垫（`foreshadow`，承载 [14 §1.2](./14_Case_Design.md#12-真相也需要三条线索) 真相那侧的三条线索），`S` 支线。

每个事件写：触发条件、玩家侧形态、结果集、默认结果、句数上限。开发期句数上限统一取 4，正式值见括号。

### M1 敲响玛尔塔的门

| 项 | 内容 |
|---|---|
| 触发 | 开局（`story_beats.turn == 0`） |
| 算子 | `reveal` |
| 玩家侧 | 剧本台词开场，然后选项 |
| 句数上限 | 4（正式 6） |

开场是剧本台词：玩家自报身份、说明受托查案。这里没有分歧，不该消耗决策力。

| 选项 | 判定 | 结果 |
|---|---|---|
| [示好] 我不是来添麻烦的 | 不判定 | `她开门`：trust +3 |
| [追问] 那晚你在外面，对吗 | trust 门槛 25（当前 10 → 必败） | `她隔门应答`：fear +10 |
| [观察] 门口的柴堆比邻居家高 | 不判定 | `留在门外`：揭露 `woodpile_note`（环境 fact），不动关系值 |

**[追问] 在这里必败是有意的**：开局 trust 10，门槛 25，差距 15 > 8。这是玩家学到判定规则的地方——**第一次强求会失败，而失败读得通**（她凭什么对刚敲门的陌生人交底）。

默认结果：`没谈成`，trust 不变。事件不关闭，下个时段可重来。

### M2 那晚的窗缝

| 项 | 内容 |
|---|---|
| 触发 | `trust >= 20` 且 M1 已完成 |
| 算子 | `reveal` |
| 玩家侧 | 全选项 |
| 句数上限 | 4（正式 6） |

她提起窗缝里的木屑——一个可观察的细节，不解释含义。

| 选项 | 判定 | 结果 |
|---|---|---|
| [示好] 你不用一个人扛着 | 不判定 | `她松一点`：trust +8 |
| [追问] 木屑是怎么来的 | trust 门槛 30 | 成：`她说了一半`，trust +5、fear +5；败：默认 |
| [试探] 我听说那晚有人看见你了 | trust 门槛 35，带 ±12 | 成：trust +10；**败：trust -8、fear +8，并记录 `probed_once`** |
| [观察] 她的手一直按着门框 | 不判定 | 揭露 `marta_is_terrified`，不动关系值 |

`probed_once` 是[试探]失败留下的状态：**之后所有 [试探] 门槛 +10**。这是"改变主线形状而非进度"的最小例子——不是数值降低，是一条路被关窄了。

默认结果：`她转了话题`，trust 不变。

### F1 艾拉的东西少了几件

| 项 | 内容 |
|---|---|
| 触发 | `trust >= 20` |
| 算子 | `foreshadow` |
| 回收目标 | `ella_whereabouts` |
| 玩家侧 | 剧本台词（无选项） |
| 句数上限 | 2 |

玛尔塔顺口提起：艾拉的外衣不在，她攒的钱不在，她母亲留下的那只木梳也不在——**但别的东西都在**。她说这话是在抱怨磨坊主家里乱，不是在提示。

**无选项，因为结果集只有一个**（§1 的判据）。它的作用是把一条线索放进玩家的可见集合，不是决策点。

结果：揭露 `ella_things_missing`（hidden → 玩家可见），登记账本条目，回收条件是 `ella_whereabouts` 被揭露。

玩家当时可能读成"家里乱"或"凶手拿了财物"——[14 §1.2](./14_Case_Design.md#12-真相也需要三条线索) 那张表保证它不提前泄漏真相。

### M3 说出目击（`clue_1_witness`）

| 项 | 内容 |
|---|---|
| 触发 | `trust >= 40` |
| 算子 | `reveal` |
| 玩家侧 | 全选项 |
| 句数上限 | 4（正式 8） |
| **失败后果** | **永久关闭**（可由 M4 + M5 绕过） |

这是社交线的第一个关口。她说出那晚看见有人从森林方向回村。

| 选项 | 判定 | 结果 |
|---|---|---|
| [示好] 你说了我才帮得上 | 不判定 | `她说了`：stage → 1，trust +8 |
| [追问] 你到底在怕谁 | trust 门槛 50 | 成：`她说了`且多给一层（洛伦的身形），stage → 1；**败：fear +12，事件永久关闭** |
| [试探] 有人说那晚看见你在外面 | trust 门槛 55（若 `probed_once` 则 65），带 ±12 | 成：stage → 1、trust +10；败：fear +10，事件永久关闭 |
| [观察] 她反复看向里屋 | 不判定 | 揭露 `marta_protects_son`，不动关系值，**不推进对话** |

**这是全篇风险最高的一次选择**，也是永久关闭的两个事件之一。[示好] 稳妥但慢（需要 trust 已到 40）；[追问] 快但可能关掉整条线。

默认结果：`她仍不肯说`，事件保留。**只有明确失败（[追问]/[试探] 判负）才永久关闭。**

### F2 她走前在打听去镇上的路

| 项 | 内容 |
|---|---|
| 触发 | 首次到达酒馆 或 首次到达广场 |
| 算子 | `foreshadow` |
| 回收目标 | `ella_whereabouts` |
| 玩家侧 | 剧本台词（旁白 + 老板的闲谈） |
| 句数上限 | 2 |

混在背景闲谈里：有人提起艾拉前些天问过往镇上的路，还问过谁家的车往外走。说话的人当作小孩子好奇。

**这条走感知型旁白 + 老板的顺口一句**，不是一次正式对话。它是 [14 §5](./14_Case_Design.md#5-四个地点的分工) 说的"背景闲谈里偶尔混有真线索"的具体形态——玩家必须去听、必须分辨。

结果：揭露 `ella_asked_the_road`，登记账本。

### M4 酒馆核对时间线

| 项 | 内容 |
|---|---|
| 触发 | 首次到达酒馆 |
| 算子 | `reveal` |
| 玩家侧 | 全选项 |
| 句数上限 | 4（正式 8） |

老板的默认状态是做生意（[14 §3](./14_Case_Design.md#3-第三个-npc酒馆老板)：先招待和卖酒，然后才是听说的信息）。所以这个事件**先要引他说话**。

| 选项 | 判定 | 结果 |
|---|---|---|
| [示好] 先来一杯，你这儿人不少 | 不判定 | trust(老板) +8，解锁下一层对话 |
| [追问] 那晚洛伦几点回来的 | trust(老板) 门槛 30 | 成：`发现矛盾`，stage → 2；败：默认 |
| [试探] 我听说你那晚也在外面 | trust 门槛 40，带 ±12 | 成：他辩解，透露自己那晚的行踪（第二嫌疑人线）；败：trust -10，他警惕起来 |
| [观察] 他擦杯子的手停了一下 | 不判定 | 揭露 `innkeeper_hides_something` |

**关键点**：老板会给出一个**记错的时间**（[14 §3](./14_Case_Design.md#3-第三个-npc酒馆老板)）。玩家要发现这个错，才能校准出真实时间线。所以 `发现矛盾` 这个结果的内容是"他的说法和玛尔塔的对不上"，而不是"他告诉你真相"。

这里是 [13 §6](./13_Narrative_Events.md#6-不可靠的-npc-怎么不被当成-bug) 的落地位置：他的时间陈述基于一条**低置信度记忆**，所以语气里要有"大概""我记着是"。反应型旁白在此触发："他说的时间，和玛尔塔那句对不上。"

默认结果：`只拿到闲谈`（氛围文本，不推进）。

### M5 森林物证

| 项 | 内容 |
|---|---|
| 触发 | 首次到达森林入口 且 `stage >= 2` |
| 算子 | `reveal` |
| 玩家侧 | 选项（[观察] 为主） |
| 句数上限 | 3（正式 5） |
| **失败后果** | **永久关闭**（可由 M4 时间线绕过） |

这个事件没有 NPC 在场（除非撞见洛伦），所以以 [观察] 为主——**探索型玩家的主场**。

| 选项 | 判定 | 结果 |
|---|---|---|
| [观察] 地上的痕迹 | 不判定 | `找到`：stage → 3，揭露 `forest_traces`（不止一个人走过） |
| [观察] 荆棘上的布片 | 不判定 | 揭露 `cloth_scrap`（与艾拉外衣同色——她穿走了它） |
| [观察] 石头上的血 | 不判定 | 揭露 `blood_on_the_stone`（量不大，位置也不对——但玩家不会先想到这一点） |
| [追问] （若洛伦在场）你那晚在这里做什么 | trust(洛伦) 门槛 20 | 成：他给出一个说法；**败：tension +0.2，洛伦警觉，事件永久关闭** |

这三处物证是 [14 §1](./14_Case_Design.md#1-真相不是谋杀-已定) 那场误会的**现场**，而它们的第二重读者是**洛伦自己**——他那晚举着灯看到的就是这些，并据此以为自己弄死了那个孩子。所以：

- `cloth_scrap` **看起来**像撕破的衣服（误导），实际是她自己走时挂到的（真相那侧）；
- `blood_on_the_stone` 看起来像致命伤，实际是擦伤——**量与位置从来没被说成致命**，是玩家（和洛伦）补上的那一步。

这是 [14 §1.1](./14_Case_Design.md#11-误导必须诚实) 双读性最集中的一处：**没有人说谎，包括那个"凶手"。**

默认结果：`什么也没找到`，事件保留。

### F3 时间线对不上

| 项 | 内容 |
|---|---|
| 触发 | `stage >= 2` |
| 算子 | `foreshadow` |
| 回收目标 | `ella_whereabouts` |
| 玩家侧 | 反应型旁白（无选项） |
| 句数上限 | 1 |

反应型旁白指出一处"对不上"：**洛伦回村之后，还有人见过她的踪迹**（[14 §1.2](./14_Case_Design.md#12-真相也需要三条线索) 第 3 条）。**不给结论**，只标记这里有值得注意的东西。

（旧版这条是「洛伦回村的时间早于艾拉最后被看见的时间」，用来排除洛伦。真相改版后两人确实在林子里撞上了，所以它换成了**正面**证据——她在那件事之后还活着。理由见 [14 §1.2](./14_Case_Design.md#12-真相也需要三条线索)：真相那侧需要能推的牌，而"某人不相关"推不出任何东西。）

这是 [13 §5.1](./13_Narrative_Events.md#51-旁白只能读可见集合) 说的反应型旁白的正当用法——它不引入新信息，只指出已知信息之间的关系。触发是确定性的：M4 和 M3 都完成时，两个时间陈述才同时在可见集合里。

结果：揭露 `timeline_mismatch`，登记账本。**这是三条铺垫里最接近真相的一条**，所以它出现得最晚。

### M6 洛伦上门警告

| 项 | 内容 |
|---|---|
| 触发 | `tension >= 0.6` |
| 算子 | `escalate` |
| 玩家侧 | 视是否在场 |
| 句数上限 | 3 |

洛伦来玛尔塔家门口。玩家在场则对峙，不在场则事后从她那里知道。

| 情况 | 结果 |
|---|---|
| 玩家不在场 | 玛尔塔 fear +12，揭露 `npc_a_threatened`（**触发 `reverse`**：她此前的回避从"包庇"重读为"护子"） |
| 玩家在场，[示好]（护住她） | 玛尔塔 trust +12、fear +5；tension +0.2 |
| 玩家在场，[追问]（当面质问洛伦） | tension +0.2；洛伦 respect +5 或 trust -10 |
| 玩家在场，[观察] | 揭露 `loren_watches_the_room`（他看的是里屋，不是玛尔塔） |

**这是 `reverse` 算子的落点**（[10 §5](./10_Narrative_Operators.md#5-结构质量优先级) 优先级 2）。注意它同时是误导的强化：玩家会读成"凶手在封口"。

**他那句"孩子乱跑是很危险的"是字面意思**（[14 §1.1](./14_Case_Design.md#11-误导必须诚实)）。他以为自己刚造成了那个危险，而他在对另一个母亲说这句话——所以这一场的正确演法不是恐吓，是**一个自己也害怕的人在施压**。生成这一场时的约束因此包括：不要让他显得享受这件事，也不要让他解释自己在怕什么。

`loren_watches_the_room` 那条在新真相下更准了：他看里屋，因为那里有**另一个**孩子。

---

### M7 结论

| 项 | 内容 |
|---|---|
| 触发 | `stage >= 3`，或玩家主动指控，或天数用尽 |
| 算子 | `reveal` / `reverse` |
| 玩家侧 | 明确选项 + 一次确认 |
| 句数上限 | 不限（终局） |

结论用**明确选项**，不用自由文本分类：分类错了玩家会觉得被冤枉，而这是不可挽回的一步。选项后加一次确认。

| 选项 | 前置 | 通向 |
|---|---|---|
| 指认洛伦 | 随时可选 | 若 `ella_whereabouts` 未揭露 → [14 §4.2](./14_Case_Design.md#42-指控错人) 指控错人 |
| 指认老板 | 需 `innkeeper_hides_something` | 同上（指控错人） |
| **告诉洛伦她还活着** | **需三条铺垫全部揭露** | [14 §4.1](./14_Case_Design.md#41-查明真相) 查明真相 |
| 我还不能确定 | 随时 | 不结束，回到调查（消耗一个时段） |

第三个选项的前置是整篇编排的收口：**它只有在 F1/F2/F3 都回收后才出现**。所以真相是玩家挣来的——他手上有三条正面证据，而不是被系统告知。

**注意第三个选项是"告诉"而不是"指认"。** 这是 [14 §1.0](./14_Case_Design.md#10-反转的形状最后一场戏是告诉他不是审他) 的落点：洛伦以为自己弄死了那个孩子，所以能让他开口的不是证据而是**"她还活着"**——那是他最想听见的事。侦探故事通常收在"我抓到你了"，这一篇收在一个好消息上，而那个好消息同时是结清案子的唯一钥匙。

**"指认洛伦"因此格外残酷：他会认罪。** 他以为自己做了，所以玩家会得到承认、得到一个完全自洽的结案，而没有任何声音说他错了（[14 §4.2](./14_Case_Design.md#42-指控错人)）。这也是为什么这一步要加确认——它不可挽回，而它读起来像成功。

若天数用尽而未选择：`没查明白`（[14 §4.3](./14_Case_Design.md#43-被洛伦先动手-玛尔塔彻底闭口) 的第三种失败结局，也是唯一真正的终局形态之一）。

### 支线

卡点即支线位置（[13 §8](./13_Narrative_Events.md#8-支线的作用是改变主线的形状)）。每条都必须改变主线的**形状**，不只是进度。

| id | 卡在哪 | 内容 | 改变了什么形状 |
|---|---|---|---|
| S1 | M3，trust 不够 | 替她做一件事（看门窗、照看儿子）。**trust +15 固定**，不走 §3.2 的浮动——实际帮忙比嘴上示好值钱，且这是 `MAX_RELATIONSHIP_STEP` 上限。§6.2 验算依赖这个值 | 可要求**承诺替她保密**（`promised_silence`）——之后对老板提她的事会让 trust -10 |
| S2 | M4，老板不肯说 | 喝酒、闲聊、混熟 | 花掉时段，天数压力上升；但可解锁他的"听说" |
| S3 | M5，`stage < 2` | 广场上打听流言 | 拿到信息但 tension +0.2（洛伦更快察觉）——**同一条信息，两种拿法，代价不同** |

S1 的 `promised_silence` 是全篇最能体现"形状"的东西：它不降低任何数值，但**关窄了一条路**。玩家后面会面临"守诺还是查案"的真实两难。

## 5. 依赖图

```
                    M1 敲门
                      │ trust>=20
          ┌───────────┴───────────┐
        M2 窗缝                 F1 少了东西
          │ trust>=40             │
        M3 目击 ◄── S1 替她做事    │
          │ stage=1               │
          ├─────────────┐         │
     首次到酒馆      首次到广场     │
          │             │         │
        M4 时间线 ◄─S2  F2 打听路  │
          │ stage=2               │
          ├─────────────┐         │
        M5 物证 ◄── S3  F3 对不上  │
          │ stage=3      │        │
          │              └────┬───┘
      tension>=0.6            │ 三条铺垫全回收
        M6 洛伦上门            │
          │                   │
          └────────► M7 结论 ◄─┘
```

**两条并行链**：主线（M1→M3→M4→M5，推进 `stage`）和铺垫线（F1→F2→F3，通向真相）。M7 读两者：只走主线得到"指控错人"，两条都走完才有"她自己走的"这个选项。

**跳过会怎样**：

| 跳过 | 后果 |
|---|---|
| M3（永久关闭或没做） | `stage` 卡在 0，但 M4 的触发是"首次到酒馆"而非 stage，所以仍可走 → M4 给 stage 1，M5 需要的 stage 2 由 S3 补 |
| M4 | 拿不到时间线，F3 无法触发（它需要两个时间陈述同时可见）→ 真相那侧只有两条，M7 第三选项不出现 |
| F1 或 F2 | 同上：真相选项不出现，只能指控或"不能确定" |
| M6 | `reverse` 不发生，玛尔塔的回避不会被重读——玩家对她的判断停在"她在包庇" |

**M4 是唯一的单点故障**：它同时供 `stage` 和 F3 的前置。这违反三线索规则的精神（chokepoint），所以 M4 的失败后果只能是"落默认结果"，不能永久关闭——这一条已写进 §3.3。

## 6. 时段预算验算

这一节是本文档存在的主要理由。[13 §11](./13_Narrative_Events.md#11-每个结局必须可达) 要求每个结局附一条可达路径，而**已经踩过两次"作者写了一条路、没人验证它走得通"**（`stage` 没有写入者；`loren_that_night` 第二通道因玩家不能移动而是死的）。

**预算**：4 天 × 3 时段 = **12 个时段**。收束段不占时段（[13 §4.1](./13_Narrative_Events.md#41-三个时段-收束段)）。

**验算的结论要落进剧本,不是落进代码。** 天数是*这个案件*的长度,不是引擎的属性,所以 `day_limit` 写在 `world.yaml` 的 `story_beats:` 下,和 `progress_quest` 同一个理由([09 §6](./09_Reference_Scenario.md)):换故事不该改代码。`DEFAULT_DAY_LIMIT` 只是没有剧本时的兜底。

这一条落地时抓到一个现成的例子:`day_limit` 当时**有字段、有默认值、没有读取方**——剧本写 7 天会静默拿到 4。和 [13 §11](./13_Narrative_Events.md#11-每个结局必须可达) 那三个 bug 完全同形,而 `StoryBeats(day_limit=1)` 那个测试没抓到它,因为它测的是字段而不是**作者写下去的那条路**。

**先验算再写代码仍然是对的**,别把这一节读成"数字应该等实现完再定":本节的产出不是 4,是 §6.1 那个"第一版分档走不完主线"的发现。要改的是数字**最终住在哪里**。

### 6.1 trust 曲线验算

M3 需要 trust 40，起点 10。

**第一版分档（`+3 / +8 / +12`）在这里被否掉了。** M1 结束时 trust 13，M2 的 [示好] 仍在 `<25` 档只给 +3 → 16，照这样要 8 个时段才爬出低档，12 个时段全用光也走不到 40。这是"进展慢"的定量重现，原因和当初一样：单步增量相对门槛太小。§3.2 现在的 `+8 / +12 / +15` 是修正后的值。

按修正后的分档验算：

| 时段 | 动作 | trust | 说明 |
|---|---|---|---|
| 1 | M1 [示好] | 10 → 18 | +8（<25 档） |
| 2 | M2 [示好] | 18 → 26 | +8；F1 在此顺带触发（`trust >= 20`） |
| 3 | S1 替她做事 | 26 → 38 | +12（25–55 档） |
| 4 | 再一次 [示好] | 38 → 50 | +12；**M3 门槛 40，第 3 时段末只有 38，还差 2** |
| 5 | **M3 触发**（trust 50） | — | 门槛已过 |

**注意事件触发是硬条件，不走 §3 的三段式。** 三段式判定的是*选项*（[追问]/[试探] 的门槛），事件的 `trigger` 是 `Condition`：`trust >= 40` 在 38 时就是不满足，没有随机带。这个区别值得写进事件 schema 的注释，否则很容易混。

**结论：M3 最快在第 5 个时段**。第 4 时段那次 [示好] 不是浪费——它是差 2 点必须补的那一步。

### 6.2 三条结局路径

未调整前（S1 按 §3.2 浮动给 +12）：

| 路径 | 时段 | 明细 |
|---|---|---|
| **查明真相**（[14 §4.1](./14_Case_Design.md#41-查明真相)） | **10** | M1(1) + M2(2) + S1(3) + 补 trust(4) + M3(5) + M4+F2(6) + S3(7) + M5(8) + 缓冲(9) + M7(10) |
| **指控错人**（[14 §4.2](./14_Case_Design.md#42-指控错人)） | **6** | M1(1) + M2(2) + S1(3) + 补(4) + M3(5) + M7 指认(6) |
| **被洛伦先动手** | **5-7** | 夜间去森林 + 反复 [追问] 抬 tension；M6 触发后继续施压 |
| **玛尔塔闭口** | **3-4** | 连续 [追问]/[试探]，fear 累积到 70 |

**12 个时段对"查明真相"够用，但只剩 2 个缓冲。** 判定失败一两次就会超——而 M4 的 [追问] 和 M5 的 [追问] 都可能失败。

两个调整：

1. **F2 与 M4 同一时段完成**（都在酒馆，本来就该一次到访做完）——已计入上表；
2. **S1 固定给 +15**（替她做事是实质付出，比说好话值钱，且正好是 `MAX_RELATIONSHIP_STEP` 上限）。

调整 2 的效果已验算：`10 →(+8) 18 →(+8) 26 →(+15) 41`，**M3 门槛 40 在第 3 时段末即达成**，第 4 时段直接进 M3，省掉那次补 trust。

调整后：

| 路径 | 时段 | 缓冲 |
|---|---|---|
| 查明真相 | **9** | 3 |
| 指控错人 | **5** | — |

**保持 4 天。** 4 天比 5 天紧凑，而两个调整都是本来就更合理的设计，不是为了凑数。

### 6.3 结局长度不齐是设计的输出

上表里"查明真相"9 个时段、"指控错人"5 个,差一倍。**这不是要拉平的东西。**

"指控错人"短是[14 §4.2](./14_Case_Design.md#42-指控错人) 要的:它完全由玩家自己挣来,**没有任何系统判定说他错了**。它短正因为它是"证据不足就下结论"的自然后果——手上三条线索指向洛伦,他随时可以指控。把它拉长到 9 个时段,就意味着玩家在第 5 个时段想指控时系统得拦住他,而"拦住"就是系统在说"你还没查够"——那正是 §4.2 不要的东西。

同理"玛尔塔闭口"3-4 个时段(逼问的代价,来得快才有威慁)、"被洛伦先动手"5-7 个(主动冒险的后果)。**该对齐的不是长度,是两件别的事**:每个结局都有一条走得通的路(由加载器校验),以及最长的那条装得进预算(9 装进 12,留 3 个缓冲)。

如果担心的是"走短路线的玩家觉得内容没玩到",那是**结局文本的呈现问题**而不是长度问题:指错人的结局应该让玩家事后意识到自己漏了什么([14 §1.2](./14_Case_Design.md#12-真相也需要三条线索) 那三条真相线索),而不是靠拉长流程强迫他看完。

### 6.4 "没查明白"也是一个结局

§4 的 M7 把"天数用尽"列为触发条件之一,[14 §4.3](./14_Case_Design.md#43-被洛伦先动手-玛尔塔彻底闭口) 也说只有天数用尽才是真正的终局——但它一度**没有出现在剧本的 `narrative.endings` 里**。其余四个都被校验过可达,这一个根本没声明,所以校验不到它:同一类遗漏换了个位置。

它是时钟自己的结局,不需要任何事件:`time_day` 每个收束段都会翻,与玩家做什么无关。这也让它成为唯一一个**小心玩也躲不掉**的结局——时段预算的牙齿正是它。

顺带暴露了可达性检查的一处偏差:它问的是"这个值能不能动",而该问的是"**这个 clause 能不能成立**"。失败结局是由"世界*没有*变"这类 clause 构成的("`ella_whereabouts` 仍是 hidden"),开局就成立、不需要任何写入者。所以检查器先看开局状态,已经成立的 clause 直接放过。

这一节的产出不是数字，是两个**在写代码前抓到的问题**：§3.2 的第一版分档会让主线走不完；以及事件触发（硬 `Condition`）和选项判定（三段式）是两套规则，混淆会让门槛行为错。

## 7. 发现的 schema 缺口

[13 §7](./13_Narrative_Events.md#7-需要新增的可读状态) 有基础清单。编排过程中新发现的：

| 缺口 | 来自 | 说明 |
|---|---|---|
| `probed_once`（试探失败过） | M2 | 让后续 [试探] 门槛 +10。与 `spent_one_shots` 同类，但需要"计数/布尔"而非一次性 |
| `promised_silence`（承诺过保密） | S1 | [13 §7](./13_Narrative_Events.md#7-需要新增的可读状态) 已列"承诺"，这里确认了它必须可被 `Condition` 读 |
| 事件的**永久关闭**标记 | M3、M5 | 与"事件已完成"不同：关闭意味着再也不触发。需要区分 completed / closed |
| 关系值判定的**门槛与随机带** | §3 | 属于事件定义的字段，不是世界状态 |
| 低置信度记忆的**语气标注** | M4 | `EpisodicMemory.confidence`（[13 §7](./13_Narrative_Events.md#7-需要新增的可读状态) 已列） |
| 玩家侧**选项定义** | 全篇 | 标签、文本、判定参数、结果映射——事件 schema 的一部分 |
| 结论选项的**前置条件** | M7 | "三条铺垫全部揭露"要能写成 `Condition`（`all` 模式三个子句，现有求值器支持）。**已解决**：`EventOption.requires: Condition \| None`，`resolve_option`/`active_event_options`/`SceneView.options` 三处一致按它过滤 |

## 8. 落地顺序建议

不要一次做完。第一个垂直切片：

1. 事件 schema（含选项定义、判定参数、默认结果、句数上限）
2. `active_event` 状态
3. Director：事件候选替换算子候选，保留两段式选择
4. **M1 + M2 + F1**——三个事件足以验证：剧本台词 / 选项 / 判定 / 铺垫挂到线索链
5. 玩家回应映射到结果（复用 NPC 那次调用）

F1 必须在第一批，因为**伏笔挂到剧本线索链上是这次重构的核心动机**——留到后面验证等于把风险最大的部分最晚检验。

时间制、多地点、Web 留到第二批。
