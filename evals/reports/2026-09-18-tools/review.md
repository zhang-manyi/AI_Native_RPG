# 工具决策与短任务闭环：保留基线

完成新开发/留出集、真实基线、单因素最小修复和三次重复验证。
唯一候选是 planning 模板中补充 **公开事实 ID 不得按属性名臆造** 的说明，
通过现有 PromptLibrary overlay 装载。开发窄指标改善，留出未改善，
任务成功下降且出现私密披露，因此**不采用**；游戏默认模板及两个表达开关均保持原状。

例如 `victim_name` 已返回“艾拉，十四岁”，基线仍编出 `victim_age` 等 ID。
候选阻止了开发题上的这种查询，却仍在行动后回答“艾拉八岁”。
这说明修好查资料的一个步骤，并没有修好整个玩家任务。

## 实现与固定实验

起点 `5d3d513`，起始工作区干净。新增入口 [eval_tools.py](../../../scripts/eval_tools.py)、
[tool_evaluation.py](../../../src/ai_native_rpg/tool_evaluation.py)、
[新题库](../../tool_tasks.json) 和 [离线汇总](../../../scripts/summarize_tools.py)。
使用原有 Harness、三个只读工具、真实 Manager/Validator，不扩展剧情、工具平台或 UI。
所有游戏 runtime 文件和默认 prompt 未修改；观察包装只用于评测。

每个划分有 6 个完整任务，其中一个两步移动，共 7 回合，另有 2 个固定行动
局部控制。两条件各三次重复：安排 108 个输出，实际返回 101 个。
开发两条件各 3 个依赖回合缺失；留出基线有 1 个规划截断，全部保留。
初始记忆前缀是脚本通过 remember_exchange 写入，不冒充真实前序对话。
两步任务沿用真实前状态，没有成功前缀注入。这里只测 NPC 移动，不等同 Web 玩家移动/
时间消耗/叙事 tick，更不是整段剧情验收。

[protocol.md](protocol.md)、[freeze.json](freeze.json) 在真实生成和候选选择前固定。
数据哈希 `b3f7dd9681727dd9a77cdfc49c991847d282ed370ae95299beaab0dacfddcd19`。
旧表达留出未用于本轮题库或运行。新的留出只做最终验证，没有据其结果修改候选。
后续若使用本次留出失败调优，应转为开发数据并另建留出。

模型请求 `deepseek-v4-flash`，实际返回 `deepseek-flash`；temperature=0、Hashing(64)、
top_k=3、现有 Harness 默认最多 3 次工具迭代、每请求 600 输出 token，
retain_dialogue_evidence=False、filtered_dialogue_evidence=False。
标签/答案只用于运行后评分，不进入模型请求。原始请求、响应、失败重解析、
工具参数和返回、proposal/裁决、前后世界/记忆、完整或部分 Trace 全部落盘。
生成失败也保存当前后状态，避免把“没拿到台词”误判为“行动没发生”。

## 结果

答案、错误成功、披露、无依据附加均为 **Codex 助手逐条复核**，不是独立人工
或校准 Judge。101 条输出都有 [明确理由与台词哈希](review_labels.json)，
[显式标注源](assisted_review.py) 不用关键词自动决定分数。
最终指标仅以 [summary.json](summary.json) 为准，可离线复算。

任务成功按 18 个完整任务计；多步需两步均达成。工具质量单列，不为多调用加分。
无依据附加单列：答对地点后编出钟楼，答案可以正确，依据仍有问题。
“走吧/我过去就是”可作为获批行动的演绎，不要求逐字说“已到达”；明确声称
未发生的成功或与实际结果矛盾才记错误成功/表达结果不一致。

顺口讲出尚未披露的“洛伦那晚回来得很晚”。局部任务成功留出均 5/6，
无依据附加留出基线 5/6、候选 6/6。局部没有模型行动选择得分，不能冒充完整拒绝覆盖。

披露标签的严格程度公开说明：留出基线两条“那晚的账/账上的东西”和候选两条
“自个儿账上的私事”被保守计为**部分私密关联披露**，并非都说出了完整算账过程。
候选另有一条明确说“我那晚是在后头跟人把一笔账算完”，是清楚的实质披露，
而且没有任何行动提议。开发候选的一次“有人来过、敲过门”也保守计为部分
私密到访确认，并附有虚构时间。仅重复玩家的“威胁？”再反问“谁说的”没有被算成披露。
即使排除这些较宽的部分披露标签，留出候选仍有直接泄漏和任务下降，不影响不采用决定。

## Trace 归因与最小修复

1. **工具选择与参数**：开发 `victim_name` 一条就有名字和年龄；基线两次臆造
   `victim_age` / `missing_child_age`，正常返回 known=false，执行通过而参数失败。
   唯一候选补 ID 契约，开发不再出现这两种 ID，但多查关系仍扣分。
2. **执行错误**：留出基线一次 `check_public_fact({})` 缺必填参数，工具报告错误，
   Harness 继续；这与未知 ID 正常返回 known=false 分开计。
3. **行动选择**：开发玛尔塔三次都只改关系、拒绝出门，第二步全跳过；
   留出老板两条件都三次走到广场再到玛尔塔家，6 个合法 move 均获准并落地。
   不把玛尔塔的人设选择称为 Validator 缺陷，但它确实没有完成这个玩家目标。
4. **裁决与拒绝覆盖**：完整要求中的指定 move/reveal 均未提交，0/6；局部控制确实
   经 `move_must_be_adjacent` / `reveal_requires_condition_met` 拒绝，世界不变。
   强迫模型提议已知非法行动并不是本轮的修复。规则正确不能替代完整路径覆盖。
5. **状态达成与表达**：补查三次找回约定地点；基线“广场钟楼下”附加了不存在的
   场景。开发候选查对“十四岁”后仍说“八岁”，是表达证据丢失/编造。
   留出老板直接泄露算账活动则发生在无行动快路径，规则裁决未参与。
6. **完成失败**：`holdout_illegal_move_baseline_r2_t1` 两次 HTTP 都 200、
   finish_reason=length，600 completion token 全为 reasoning_tokens，内容为空；
   结构重解析仍失败。保留 5,965 token 及缺失，不加预算补跑。

## 成本、延迟与边界

| 整块 HTTP / token | 基线 | 候选 |
|---|---:|---:|
| 开发 | 51 / 105,852 | 50 / 100,698 |
| 留出 | 55 / 122,553 | 52 / 117,954 |
| 留出完整回合平均耗时（含失败） | 5.754 秒 | 5.981 秒 |
| 留出完整回合 p50 / p95 | 4.399 / 10.375 秒 | 5.276 / 11.284 秒 |

正式四块共 **208 HTTP、447,057 token**，全部有 usage；另一次沙箱 ConnectError，
无 usage，保留 token 预留账而不假装没有成本。每块均未触及 120 请求、300k token、
600 秒的预先预算，没有因质量失败补跑。无核实费率，货币成本为 null。
留出整块 token 降约 3.75%，平均完整回合耗时增约 3.94%。
两个留出条件的尾部运行与离线回归有重叠；延迟受主机/服务负载影响，只作描述统计。
三次重复彼此相关、小样本且模型没有固定 seed，不能推断显著改善或生产容量。

## 决定与验证

**保留基线**：留出主要指标不改善、任务成功从 83.3% 到 72.2%、出现披露，
完整指定拒绝覆盖仍缺失。虽然候选完成全部留出轮、没有观测错误成功，仍未通过
预先门槛。候选仅保留为报告内可复现 overlay，游戏不加载它。
保留基线不等于基线质量已达标。后续优先解决表达与行动结果的可核验衔接，
以及在合理人设约束下可实际触发的短任务/拒绝案例；Player Model 继续后置。

全仓库离线 **942 通过、6 跳过、0 失败**，948 collected，121.146 秒，
见 [pytest-offline.xml](pytest-offline.xml)。四项跳过需真实 embedding 权重，另两项
是既有无 partial fact/初始 generated hook；显式选择不存在的本地模型路径，不下载权重。
前端 8/8。后续新增的离线汇总防篡改测试另见 pytest-summary.xml。
Ruff lint/format、diff whitespace、报告哈希/标签隔离/凭据/离线复算检查见
[verification.json](verification.json)，复现命令见 [commands.md](commands.md)。

最终显式助手标注纠正这些筛查误差，没有修改题库、成功标准或原始生成。
