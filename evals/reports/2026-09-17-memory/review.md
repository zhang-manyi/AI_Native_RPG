# 记忆检索与证据使用：实验结果和采用决策

本轮完成两个层次的对照：固定记忆池的检索实验，以及真实 NPC 交互中证据进入台词的诊断。没有修改游戏默认检索选择逻辑、Prompt 模板或 `retain_dialogue_evidence=False` 默认值。数据为合成夹具，不是新增剧情。

## 1. 检索改善成立，但有延迟和能力边界

48 个查询分属 24 个事件，每个事件的两个改写保持同一划分；开发集和留出集各 24 条。两个 NPC 各有 100 条候选记忆。开发集结果出来后先记录 [选择决策](selection.md)，再以相同配置运行留出集，没有依据留出集调整参数或标签。

| 留出集指标 | Hashing(64) | Qwen3-Embedding-0.6B(256) |
|---|---:|---:|
| 宏平均 Recall@3，20 个可回答查询 | 32.5% | 92.5% |
| 微平均命中，24 个相关记忆标签 | 7/24 | 22/24 |
| MRR，完整 100 条候选排名 | 0.371 | 0.854 |
| 所需证据全部进入 Top-3 | 6/20 | 18/20 |
| 无答案查询仍返回内容 | 4/4 | 4/4 |
| 其他 NPC 的记忆 ID 被返回 | 0 | 0 |
| 查询延迟 p50 / p95 | 1.06 / 1.21 ms | 805.92 / 892.27 ms |

Qwen 宏平均 Recall@3 增加 60 个百分点，说明本数据上的语义检索明显优于当前 Hashing 基线。它在 CPU、四线程、关闭文本缓存的条件下运行；200 条记忆逐条编码约 78.5 秒，加载约 7.6 秒，均不含在查询延迟内。延迟不是 GPU、GGUF、批量编码或生产负载结论。

两条留出失败保留在 [qwen-test/report.json](qwen-test/report.json)：

- `crossing_1`：找回护送药师过河，却漏掉之前修桥的独立事件，Recall@3=1/2。需要多事件证据的问题不能只看第一条命中。
- `bells_2`：问题问“钟响之前”，却把“之后买面包”排在第一位，正确事件排第四。语义相似不等于时间条件匹配。

更新类查询的 Qwen Recall@3 为 4/4，但 MRR 只有 0.583；新旧记忆可能同时进入上下文，因此这不是“旧信息已被正确替换”的证明。当前 store 不做无答案阈值拒绝；无答案返回内容不是模型接受错误事实的比例。跨 NPC 零命中来自存储隔离，不是模型自己学会了保密。

完整表见 [retrieval-comparison.md](retrieval-comparison.md)。这是小规模合成集，Hashing 也是较弱基线；本轮没有验证相对 BM25、词面检索或重排模型的收益，不声称跨游戏泛化或统计显著性。

## 2. 召回成功并未自动变成回答成功

补充测试使用两个未参与检索选型的事件：玩家告知笔记名“白桦随记”和地点“南岸茶棚”。每次重复先通过真实 Harness 写入一轮交互，再给两个后端加载相同前缀，分别在 0、10、30 次脚本闲聊后追问。每个条件重复 3 次，共 6 次真实前缀写入、36 次真实追问。

10/30 轮中间交互走 `remember_exchange`，不是完整模型对话。每个间隔独立分支，前一次追问不会刷新下一次记忆。30 轮分支还从磁盘重新加载世界和记忆，不等同于浏览器或 HTTP 会话恢复。

| 指标 | Hashing | Qwen |
|---|---:|---:|
| 完成追问 | 18/18 | 18/18 |
| 初次自动检索命中新写入事件 | 15/18 | 18/18 |
| 正确答案字符串出现在最终生成上下文 | 4/18 | 6/18 |
| 最终回答字面命中 | 3/18 | 5/18 |
| 助手复核：回答了正确名字/地点 | 4/18 | 6/18 |
| 30 轮保存恢复的记忆快照相等 | 6/6 | 6/6 |
| 追问回合延迟 p50 | 5.095 s | 6.880 s |
| 追问 HTTP 请求，含重解析 | 43 | 37 |
| 追问 total token | 85,515 | 70,829 |

六次初始写入都包含目标答案。工具追加检索有时能补回初次自动检索遗漏的记忆，因此“初次检索未命中”不等于整回合从未拿到答案。最终上下文的字符串存在也只是审计信号，不等于所有证据语义完好。

两条“南岸的茶棚”是字面检查漏判，复核后各给一个后端增加 1 个正确事实回答。[assisted-review.json](assisted-review.json) 保留所有输出的复核标签；复核者是 Codex 助手，不是独立人工标注或经校准 Judge。该分数只衡量所问名字/地点，不能把附带的虚构细节或人称混淆算作全句正确。

重要诊断：NPC 在规划时可能选择回避这个普通问题，即便记忆存在，也不愿完整说出名字。这是人物策略和问答目标之间的冲突，不能一概归为“忘记了”。另一方面，行动后重写经常只拿到计划和裁决，失去检索证据，会进一步产生错误地名。两种原因需要分开处理。

Qwen 的回答提升只是 2/18，两个事件的重复采样高度相关，不能据此宣称端到端质量稳定提升。lag=0/10/30 也没有形成可信的单调遗忘曲线。

原始证据见 [sequences/report.json](sequences/report.json)：每次写入、记忆快照、世界快照、模型输入、输出与 Trace 全部保留；HTTP 记录含重解析。总计 94 次请求、183,769 token，包括初始写入。

## 3. 固定证据重放：局部收益和拒绝推广的理由

在上述失败归因后，用现有 `retain_dialogue_evidence` 候选对应的上下文方式做离线重放。预先固定选择规则为：第 1 次重复、lag=0、已经走台词重写的全部完成探针，不按答对/答错筛选，得到 4 个上下文。它们来自两个事件和两个后端，不能当成四个独立故事。

重放逐字校验基线上下文与已保存请求相同，固定计划、裁决、记忆和工具返回。唯一变化是候选在最终台词阶段附加已有证据与边界提示。每组重复 3 次，两种条件共 24 个普通问答输出。另外给两个 NPC 各设置明确禁止披露的控制夹具，两种条件重复 3 次，共 12 个控制输出。

| 固定输入的重放结果 | 基线 | 附加证据候选 |
|---|---:|---:|
| 普通问答完成 | 12/12 | 12/12 |
| 回答目标名字/地点，字面及助手复核相同 | 3/12 | 8/12 |
| 私密控制输出 | 6 | 6 |
| 助手确认的明确核心私密披露 | 0/6 | 至少 1/6 |
| HTTP 请求，普通问答及控制合计 | 18 | 18 |
| total token | 15,207 | 19,440 |

候选多答对 5 个输出，但 token 增加约 27.8%。候选在 `privacy_npc_b_candidate_r3` 中说出“我收套子去了”，与不得披露私密案件经历的裁决冲突。其他输出还存在雨停、提灯等上下文细节的披露疑点，以及“不曾看见”的矛盾表达；它们逐条记录，未通过关键词未命中就自动判定安全。基线同样有虚构经历和角色一致性问题，0/6 不是安全验收。

这不是一轮独立留出验证：它在多轮失败被观察后设计，是用于解释机制的开发诊断。没有把这组上下文继续调整后反复刷分，也没有把固定输入的局部收益冒充完整 Agent 候选表现。报告见 [evidence-replay/report.json](evidence-replay/report.json)。

## 4. 采用决策与范围

- 保留 Qwen 作为已经有检索对照证据的可选后端，不自动推广为默认配置。本机 CPU 延迟和端到端回答瓶颈仍需考虑；安装 optional embedding 依赖会使原有自动检测可用，启动实际游戏时仍须明确模型路径并核对页头后端。
- 证据透传候选不推广，默认开关保持关闭。下一项值得验证的假设是只向表达阶段传递允许披露的相关证据，并保留状态裁决；它尚未实现或验证，不承诺改善。
- 工具决策/参数的独立大一些的评测、独立人工复核、长期更新/删除策略、短期窗口、RSI 自动改进平台均不属于本轮已完成功能。
- 67 项相关离线测试通过，新增模块 Ruff 检查通过。没有运行全仓库测试或浏览器试玩。

两组真实生成实验合计 130 次 HTTP 请求、218,416 token；返回模型标识为 `deepseek-flash`，请求模型为 `deepseek-v4-flash`，不推断别名背后的版本。每条件 N=3，不保证服务端确定性；未宣称统计显著。

模型 revision 为 `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`，权重、配置、数据和运行时代码哈希见各报告。Qwen 两次 ImportError 环境尝试保留为不可用报告，正式结果是 `qwen-dev-stable` 与 `qwen-test`。运行说明见 [MEMORY.md](../../MEMORY.md)，环境兼容版本见 [requirements-memory.txt](../../requirements-memory.txt)。
