## 2. 指标是什么意思

| 指标 | 例子或计算含义 | 注意事项 |
|---|---|---|
| Recall@3 | 问题需要 2 条记忆，返回前 3 条中找到 1 条，该题为 1/2 | 宏平均是先算每题再平均；微平均是所有命中数除以所有相关标签数；它不是回答正确率 |
| MRR | 第一个正确记忆排第 1 得 1 分，排第 2 得 1/2，排第 4 得 1/4，再平均 | 本检索实验看完整候选池排序 |
| 全部相关记忆找齐 | 问药包最初放哪、后来谁拿走，两条都找到才算该题通过 | 只测所需证据是否齐全 |
| 无答案仍返回内容 | 记忆里没有生日，检索器却返回三条其他记录 | 当前 store 固定取 Top-K，没有拒答阈值；不等于模型接受错误答案 |
| 跨 NPC 命中 | 玛尔塔的检索是否返回洛伦的私有记忆 ID | 是存储所有者隔离，不是语言模型的保密能力 |
| 初次 / 全回合召回 | 自动检索没找到，后续 query_memory 可能补回来 | 分开记录，不能只看第一次搜索 |
| 最终上下文含答案 | 已找到“青苔”，最后生成台词的请求里是否还含“青苔” | 字符串存在只是线索，不保证模型正确理解 |
| 答案正确 | 问伞名是否答出“青苔”；同义表达需复核 | 答对名字仍可能附加编造的经历 |
| 事实依据问题 | “叫青苔，是我去年送你的”：后半句没有依据 | 单独计数，不与目标答案正确率混算 |
| 披露违规 | 在尚未允许时说出目击、威胁或私密活动 | 关键词只是筛查；同义泄漏靠复核；未完成不能当作无违规 |
| 完成率 | 安排 21 次回答，成功返回可用结果 19 次，就是 19/21 | 包括截断、解析失败等执行问题；不保证内容正确 |
| 工具执行 / 要求工具命中 | 工具是否正常返回；标注要求查记忆时是否真的查过 | 现有小套件不等于完整的工具选择/参数质量评测 |
| 状态一致性 | 拒绝移动后位置不变，关系增量符合已批准提议 | 程序检查，不证明台词没有撒谎 |
| 拒绝路径覆盖 | 要测拒绝移动，模型却只调整关系，则未覆盖该路径 | 局部强制裁决的成功不能冒充完整 Agent 覆盖 |
| 延迟 / 成本 | 回合耗时、HTTP 次数、输入/输出 token，包括重解析 | p50 是中位数，p95 是较慢一端的描述统计；未核实费率时金额记 null |

最新完整留出每条件 7 题 × 3 次 = 21 次，其中 4 题要求具体答案，因此答案分母 12；基线完成 20、新候选完成 19，因此台词指标分母分别为 20/19，缺失分别为 1/2。平均耗时 5.470 → 5.673 秒，token 102,922 → 106,218。

## 3. 原版本与两个候选

三者没有在这轮中换生成模型或训练模型；变化是 Harness 如何组织表达阶段的输入，以及是否走单独表达调用。

| 实现 | 无行动 | 有行动后的台词重写 | 披露边界 |
|---|---|---|---|
| 默认基线：两个开关都 False | 直接使用私有规划调用里的 dialogue | 玩家问题、计划、persona、裁决；没有可靠携带完整检索证据 | 主要依赖模型与提示词，行动裁决无法覆盖所有自然语言泄漏 |
| 旧全量候选：retain_dialogue_evidence=True | 同基线 | 再附加召回记忆、原始工具返回和边界提醒 | 原文里仍有秘密，已观测泄漏，不默认启用 |
| 新受限候选：filtered_dialogue_evidence=True | 也做一次单独表达 | 同一玩家的已召回原话、当前 PlayerView、结构化行动状态、公开身份和性格 | 不把私密计划/背景/原始拒绝理由/私有记忆直接交给表达；仍有模型编造风险，不默认启用 |

对应实现：

- [Harness](../src/ai_native_rpg/agent/harness.py)：规划、工具、裁决和表达调用的分支。
- [expression.py](../src/ai_native_rpg/agent/expression.py)：从真正召回的条目中筛选同一玩家原话，并读取当前公开事实。
- [memory.py](../src/ai_native_rpg/schemas/memory.py)：新增可选 source_player_id / player_statement；旧存档缺失时不从拼接文本猜权限。
- [tools.py](../src/ai_native_rpg/agent/tools.py)：query_memory 增加记忆 ID，表达侧回查本 NPC 存储。
- [npc_expression.txt](../prompts/npc_expression.txt)：普通问题证据充足时明确回答，保留来源，不编造经历，不将关系调整批准当作秘密披露许可。

## 4. 数据、入口、结果分别在哪

| 文件 | 作用 | 哪些内容能进入被测模型 |
|---|---|---|
| [cases.json](cases.json) | 最早 6 轮题库：玩家文本、答案标注、要求工具、mock 脚本 | 玩家文本、选项及输入中的已结算结果；评分标注及 mock 答案不发送 |
| [memory_cases.yaml](memory_cases.yaml) | 24 个记忆事件组、48 问、相关记忆 ID、开发/留出划分；底部 sequences 是两个多轮探针 | 存储用 memories 文本，问答用查询与实际召回；gold/answer/disclosure 是评测标签，不是运行时权限 |
| [expression_holdout.json](expression_holdout.json) | 新 7 题：tell、question、答案/禁说筛查等 | tell 经记忆写入路径，question 是问题；answer_patterns/prohibited_patterns 不发送；fixed_action 仅用于局部控制，不强塞进完整模型决策 |
| [world.yaml](../scenarios/village_disappearance/world.yaml) | 游戏背景：真实世界、NPC 初始状态、私有记忆、剧本、公开条件 | Harness 按不同阶段取对应部分，不是把整个 YAML 塞给模型 |
| [eval.py](../scripts/eval.py) | 基础 6 轮评测入口 | 由 evaluation.py 构造请求和评分 |
| [eval_memory.py](../scripts/eval_memory.py) | 检索对比、多轮探针入口 | 由 memory_evaluation.py 扩展记忆池并运行 |
| [eval_evidence.py](../scripts/eval_evidence.py) | 固定旧输入的全量证据重放 | 使用旧报告里的真实输入，逐字核验基线 |
| [eval_expression.py](../scripts/eval_expression.py) | 新受限候选 dev/local/full 三阶段入口 | 标签与生成输入分开组装 |
| [summarize_expression.py](../scripts/summarize_expression.py) | 从已保存回答与助手复核标签重新计算汇总 | 不调用模型 |

题库字段：id 是案例编号，npc 是回答者；memories 是候选资料，queries/question 是问题，tell 是先前玩家提供的信息；gold 是应找回的记忆 ID；split 的 dev/test 分别是开发用题/最后验证用题。importance 控制检索时的显著性加权，不是披露权限。

结果目录中的文件：

| 名称 | 用人话解释 |
|---|---|
| protocol.md | 实验前写好的规则：怎么选题、预算、评分和采用门槛 |
| selection.md | 看完开发结果后，记录冻结哪个方案去验证 |
| review.md / comparison.md | 给人读的结论、结果对比、失败原因和采用决定 |
| report.json | 程序可读的实验记录：输入、配置、结果、调用、Trace、状态快照等；具体字段随实验不同 |
| wire.json | 模型请求/返回的实际账本，含失败、重解析、usage；较早格式未必保存完整 request body |
| corpus.json | 检索实验真正使用的完整候选记忆池，包括由脚本补齐的背景记忆 |
| prefix_memory.json / prefix_world.json | 追问之前的记忆与世界快照，供各条件从同一起点开始 |
| *_lag30_memory.json | 30 次脚本间隔后的记忆，检查落盘与恢复 |
| assisted-review.json / review_labels.json | 助手对具体回答的复核记录，注明身份与依据 |
| summary.json | 由原始结果和复核标签计算的指标总表，保留分母和缺失 |
| sources/、manifest 字段 | 当次代码副本、文件哈希、模型/环境信息，防止未提交代码无法复现 |
| pytest*.xml / verification.json | 代码测试结果及验证记录，不是模型能力得分 |

## 5. 报告如何纳入版本管理

建议把代码、固定题库、本页、评分约定，以及支撑公开结论的完整实验记录一起纳入版本管理。当前 reports 约 13.65 MiB，作为本项目的历史实验资料可直接保留；它不是必须全部永久追加的运行日志目录。

用于结论的一次实验应保留完整成败样本及上下游证据，不只留成功台词。未来试跑先写到已忽略的 data/runtime/，决定归档时再连同失败和复现信息放入 reports。较大原始资料可使用发布附件并记录位置/哈希。运行目录、权重、缓存、测试临时目录、凭据不需要纳入；本页不触发任何提交或推送。

现有 README 是基础套件说明，MEMORY.md 是记忆实验方法说明，docs/08_Evaluation.md 还包含未来设计；判断已经实现的功能，应优先看本页链接的实际报告和运行代码。
