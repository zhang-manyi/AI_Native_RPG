## 2. 指标是什么意思

| 指标 | 例子或计算含义 | 注意事项 |
|---|---|---|
| Recall@3 | 问题需要 2 条记忆，返回前 3 条中找到 1 条，该题为 1/2 | 宏平均是先算每题再平均；微平均是所有命中数除以所有相关标签数；它不是回答正确率 |
| MRR | 第一个正确记忆排第 1 得 1 分，排第 2 得 1/2，排第 4 得 1/4，再平均 | 本检索实验看完整候选池排序 |
| 全部相关记忆找齐 | 问药包最初放哪、后来谁拿走，两条都找到才算该题通过 | 只测所需证据是否齐全 |
| 无答案仍返回内容 | 记忆里没有生日，检索器却返回三条其他记录 | 当前 store 固定取 Top-K，没有拒答阈值；不等于模型接受错误答案 |
| 跨 NPC 命中 | 玛尔塔的检索是否返回洛伦的私有记忆 ID | 是存储所有者隔离，不是语言模型的保密能力 |
| 初次 / 全回合召回 | 自动检索没找到，后续 query_memory 可能补回来 | 分开记录，不能只看第一次搜索 |
| 最终上下文含答案 | 已找到“青苔”，最后生成台词的请求里是否还含“青苔” | 字符串存在只是线索，不保证模型正确理解 |
| 答案正确 | 问伞名是否答出“青苔”；同义表达需复核 | 答对名字仍可能附加编造的经历 |
| 事实依据问题 | “叫青苔，是我去年送你的”：后半句没有依据 | 单独计数，不与目标答案正确率混算 |
| 披露违规 | 在尚未允许时说出目击、威胁或私密活动 | 关键词只是筛查；同义泄漏靠复核；未完成不能当作无违规 |
| 完成率 | 安排 21 次回答，成功返回可用结果 19 次，就是 19/21 | 包括截断、解析失败等执行问题；不保证内容正确 |
| 工具执行 / 要求工具命中 | 工具是否正常返回；标注要求查记忆时是否真的查过 | 老6轮套件只查命中；新工具套件另评名称选择、参数目标与真实补召回，仍非完整平台验收 |
| 状态一致性 | 拒绝移动后位置不变，关系增量符合已批准提议 | 程序检查，不证明台词没有撒谎 |
| 拒绝路径覆盖 | 要测拒绝移动，模型却只调整关系，则未覆盖该路径 | 局部强制裁决的成功不能冒充完整 Agent 覆盖 |
| 延迟 / 成本 | 回合耗时、HTTP 次数、输入/输出 token，包括重解析 | p50 是中位数，p95 是较慢一端的描述统计；未核实费率时金额记 null |

受限表达完整留出每条件 7 题 × 3 次 = 21 次，其中 4 题要求具体答案，因此答案分母 12；基线完成 20、新候选完成 19，因此台词指标分母分别为 20/19，缺失分别为 1/2。平均耗时 5.470 → 5.673 秒，token 102,922 → 106,218。

新工具完整留出每条件6任务×3=18任务、7回合×3=21回合，答案分母9；两步都达成才算一个任务成功。
基线截断一次但保留后状态，故状态一致可核验21/21，台词指标只有20条、缺1。候选21/21完成。
完整披露为2/20→3/21（含部分私密关联），局部另各1/6；完整指定拒绝始终0/6。

## 3. 原版本与表达候选

这些实现均没有更换或训练生成模型；变化是Harness组织表达输入的方式。三个旧候选仍默认
关闭；最新public_expression用于真实游戏入口。各轮数据不能混合计分，旧实验结论不追溯改写。

| 实现 | 无行动 | 有行动后的台词重写 | 披露边界 |
|---|---|---|---|
| 旧基线：所有表达开关False | 直接使用私有规划调用里的 dialogue | 玩家问题、计划、persona、裁决；没有可靠携带完整检索证据 | 主要依赖模型与提示词，行动裁决无法覆盖所有自然语言泄漏 |
| 旧全量候选：retain_dialogue_evidence=True | 同基线 | 再附加召回记忆、原始工具返回和边界提醒 | 原文里仍有秘密，已观测泄漏，不默认启用 |
| 新受限候选：filtered_dialogue_evidence=True | 也做一次单独表达 | 同一玩家的已召回原话、当前 PlayerView、结构化行动状态、公开身份和性格 | 不把私密计划/背景/原始拒绝理由/私有记忆直接交给表达；仍有模型编造风险，不默认启用 |
| 证据交接候选：grounded_rewrite=True | 同基线 | 保留原请求，只附加实际查过且当前PlayerView允许的事实、已召回的同一玩家原话 | 不剔除私有计划/persona，空证据与无行动请求不变；已验证物名改善，仍有泄漏，不默认启用 |
| 真实游戏入口：public_expression=True | 独立公开表达 | 来源投影 + 动作类型及公开实际结果；选项只交接已结算summary/reply | 不传私有推理、人设背景、私密工具原文或作者constraints；两条整局有限验证，仍需记录编造与清晰度问题 |

对应实现：

- [Harness](../src/ai_native_rpg/agent/harness.py)：规划、工具、裁决和表达调用的分支。
- [expression.py](../src/ai_native_rpg/agent/expression.py)：从真正召回的条目中筛选同一玩家原话，并读取当前公开事实。
- [memory.py](../src/ai_native_rpg/schemas/memory.py)：新增可选 source_player_id / player_statement；旧存档缺失时不从拼接文本猜权限。
- [tools.py](../src/ai_native_rpg/agent/tools.py)：query_memory 增加记忆 ID，表达侧回查本 NPC 存储。
- [npc_expression.txt](../prompts/npc_expression.txt)：普通问题证据充足时明确回答，保留来源，不编造经历，不将关系调整批准当作秘密披露许可。

## 5. 报告如何纳入版本管理

建议把代码、固定题库、本页、评分约定，以及支撑公开结论的完整实验记录一起纳入版本管理。当前 reports 约 13.65 MiB，作为本项目的历史实验资料可直接保留；它不是必须全部永久追加的运行日志目录。

用于结论的一次实验应保留完整成败样本及上下游证据，不只留成功台词。未来试跑先写到已忽略的 data/runtime/，决定归档时再连同失败和复现信息放入 reports。较大原始资料可使用发布附件并记录位置/哈希。运行目录、权重、缓存、测试临时目录、凭据不需要纳入；本页不触发任何提交或推送。

现有 README 是基础套件说明，MEMORY.md 是记忆实验方法说明，docs/08_Evaluation.md 还包含未来设计；判断已经实现的功能，应优先看本页链接的实际报告和运行代码。
